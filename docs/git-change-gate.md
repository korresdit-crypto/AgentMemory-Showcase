# 🌳 Git Change Gate

Git Change Gate — механизм контроля изменений перед попаданием кода в основную ветку.

## Зачем он нужен

AI-исполнитель не должен самостоятельно:

- изменить код;
- проверить собственную работу;
- решить, что всё корректно;
- сразу отправить изменения в main.

AgentMemory разделяет эти этапы.

## Упрощённый процесс

```text
Task
  ↓
Isolated Worktree
  ↓
Implementation
  ↓
Automated Tests
  ↓
Independent Review
  ↓
Change Gate
  ↓
Human Approval
  ↓
Push / Merge
```

## Изоляция

Для задачи может создаваться отдельная Git-ветка и worktree.

Основная рабочая копия при этом остаётся отдельно от изменений AI.

## Preflight checks

Перед разрешением дальнейших действий система проверяет:

- соответствие задачи и Git-состояния;
- корректность base/result commit;
- результаты обязательных тестов;
- `git diff --check`;
- чистоту основной рабочей копии;
- отсутствие неожиданных файлов;
- потенциальные секреты;
- независимый review;
- отсутствие критических замечаний.

## Independent Review

Результат реализации может отдельно проверяться другим AI-исполнителем.

AgentMemory не полагается только на утверждение модели о том, что её собственный код готов к merge.

## Human Approval

Даже успешный Change Gate не обязан автоматически выполнять merge.

Критические действия могут требовать отдельного подтверждения человека.

## Fail-Closed

Если проверка:

- не выполнена;
- получила неполные данные;
- обнаружила рассинхронизацию;
- не смогла подтвердить состояние репозитория;

операция блокируется вместо автоматического продолжения.

## Цель

Git Change Gate превращает работу AI с кодом из:

```text
AI написал → AI решил, что всё хорошо → merge
```

в более контролируемый процесс:

```text
AI написал
   ↓
система проверила
   ↓
другой reviewer проверил
   ↓
человек подтвердил
   ↓
merge
```
