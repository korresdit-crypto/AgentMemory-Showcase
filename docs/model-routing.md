# 🧭 Model Routing

AgentMemory использует собственный слой маршрутизации задач между AI-моделями.

Цель Model Router — не отправлять все задачи одной модели, а выбирать исполнителя в зависимости от роли, типа задачи и доступности конкретного AI.

## Основные роли

```text
IMPLEMENTER  → Codex
ARCHITECT    → Claude
CRITIC       → Claude
LOCAL_WORKER → Qwen
RESEARCHER   → Research route
```

## Как работает маршрутизация

При запуске задачи система учитывает:

- тип задачи;
- требуемую роль;
- доступность AI-исполнителя;
- ограничения конкретного workflow;
- необходимость локального или облачного выполнения;
- необходимость дополнительной проверки результата.

## Приоритет выбора

```text
Explicit executor
       ↓
Role routing
       ↓
Default / fallback
```

## Разделение ответственности

### Codex

Используется прежде всего для:

- реализации;
- работы с кодом;
- изменений в Git-репозиториях;
- выполнения задач IMPLEMENTER.

### Claude

Используется прежде всего для:

- архитектурного анализа;
- критики решений;
- независимого review;
- ролей ARCHITECT и CRITIC.

### Qwen

Локальная модель для:

- предварительного анализа;
- классификации;
- локальных проверок;
- дешёвых независимых оценок;
- задач LOCAL_WORKER.

### Research route

Используется для задач, где нужен внешний поиск, актуальная информация или независимое исследование.

## Принцип

AgentMemory строится вокруг идеи:

> одна модель не должна одновременно быть автором решения, единственным проверяющим и финальным арбитром собственного результата.

Поэтому маршрутизация отделена от проверки и финального контроля.
