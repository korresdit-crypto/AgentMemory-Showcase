# 🚦 Review Severity

Независимый review должен различать важность найденных проблем.

## Типичный смысл уровней

### BLOCKER

Проблема, из-за которой результат нельзя принимать.

### IMPORTANT

Существенная проблема, требующая исправления или отдельного решения до финального принятия.

### MINOR

Небольшое замечание, которое не обязательно блокирует весь workflow.

### OPTIONAL

Рекомендация или улучшение, не являющееся обязательным условием принятия.

## Зачем нужна severity

Без severity все findings выглядят одинаково, хотя их влияние на решение различается.

## Упрощённая логика

```text
Review Findings
      ↓
Severity Classification
      ↓
Blocking Findings?
      ├─ Yes → BLOCKED
      └─ No  → Continue
```

## Принцип

Финальное gate-решение не должно зависеть только от общего текстового впечатления reviewer.

Структурированная severity помогает сделать решение более предсказуемым.
