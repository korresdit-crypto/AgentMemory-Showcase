# 🚨 Failure Handling

AgentMemory проектируется так, чтобы ошибки не превращались в неявный успех.

## Возможные сбои

- AI provider недоступен;
- CLI не запускается;
- превышен timeout;
- ответ не соответствует контракту;
- контекст невозможно безопасно сформировать;
- Git-состояние изменилось;
- тесты не прошли;
- recovery не может определить безопасную точку продолжения.

## Общий подход

```text
Failure
   ↓
Classify
   ↓
Record safe technical state
   ↓
Retry / Fallback / Block
   ↓
Human intervention if required
```

## Safe errors

В долговременное состояние не должны автоматически попадать:

- секреты;
- полные environment variables;
- необработанные provider responses;
- приватные пути и credentials;
- чувствительные данные из исключений.

## Fail-Closed

Если система не может доказать корректность продолжения, workflow блокируется.

## Цель

Ошибки должны быть:

- наблюдаемыми;
- классифицируемыми;
- воспроизводимыми;
- безопасными для логирования;
- пригодными для recovery.
