# 🗃 Runtime State

AgentMemory хранит техническое состояние workflow отдельно от человекочитаемой проектной памяти.

## Зачем это нужно

Долговременная память проекта отвечает на вопрос:

> Что мы знаем о проекте?

Runtime state отвечает на другой вопрос:

> Что сейчас происходит с конкретным запуском?

## Runtime State может содержать

- идентификатор run;
- текущий stage;
- состояние задачи;
- результаты gate-проверок;
- ссылки на артефакты;
- технические события;
- сведения о recovery;
- bounded audit metadata.

## Упрощённая схема

```text
Project Memory
     │
     └── долгосрочные знания

Runtime State
     │
     └── состояние конкретного workflow
```

## Принцип

Рабочее состояние выполнения не должно подменять каноническую память проекта.

После завершения workflow значимые выводы могут быть отдельно зафиксированы в долговременной памяти.
